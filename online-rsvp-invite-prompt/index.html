The online RSVP invitation — the full prompt

This is the prompt behind the invitation from this week’s email — the pretty flyer, the RSVP form guests fill in right on the page, and the live “Who’s coming” list the host can actually track. It started as my book club invitation, but it works for any event: fill in the brackets with your party’s details, then paste the whole thing into your AI tool and let it build and host the page for you.

🎉 You only need to fill in the brackets: your event, the host, the date, and the address (or “shared privately”). Everything else — the design, the RSVP form, the live guest list — is already spelled out in the prompt, with examples for a book club, a birthday, a girls dinner, and a holiday party.

EDIT THESE FIRST — replace every [BRACKET] before you paste: [EVENT NAME] — the name of your event, e.g. "A Very Merry Grinchmas", "Maddie's 40th Birthday", "Girls Dinner", "Neighborhood Book Club" [EVENT TYPE] — birthday, girls dinner, holiday party, Thanksgiving, baby shower, book club, dinner party... this drives the wording, so say it plainly [HOST NAME(S)] — e.g. Charlotte, or Hosted by Sue Fox [WEEKDAY, DATE] — e.g. Saturday, December 6 [TIME] — e.g. 5:00 PM (add an end time if you have one) [ADDRESS] — the address as plain text, or write "Address shared privately" if it shouldn't sit on a public page [THEME / LOOK] — the season, colors and vibe, e.g. "cozy Christmas — cream, deep red, evergreen and gold" or "glam winter birthday — blush, cream and gold sparkle" or "summer garden party — sage, white and lemon" [FEATURE IMAGE] — the one picture the invitation is built around: the actual book cover for a book club, a themed illustration or photo for anything else. Describe it if you want the AI to create it. [INTRO LINE] — one warm line inviting people, in your words [DETAILS BULLETS] — 1–3 short bullets guests should know: what to bring, what to wear, parking, kids or adults only. Short bullets, never a paragraph. [EMOJI] — one emoji that fits the theme, used sparingly (🎄 ✨ 🎂 🌸) Worked examples — same prompt, different events: • Book club: [EVENT NAME] Neighborhood Book Club · [FEATURE IMAGE] the actual cover of this month's book, on a table by a fireplace with a mug of cocoa · [DETAILS BULLETS] one question to ponder as you read • Birthday: [EVENT NAME] Maddie's 40th · [FEATURE IMAGE] a glam winter illustration, feathers and gold · [DETAILS BULLETS] dress to impress, no jeans · adults only • Girls dinner: [EVENT NAME] Girls Dinner at Rosa's · [FEATURE IMAGE] a candlelit table illustration · [DETAILS BULLETS] bring a bottle to share · parking in the back lot • Holiday party: [EVENT NAME] Mingle & Jingle · [FEATURE IMAGE] a watercolor of the host's house at Christmas · [DETAILS BULLETS] bring a dish to share · one wrapped ornament under $15 for the exchange Step 1 — Build the invitation page: Build me a single, self-contained HTML page for my event — a beautiful invitation with working RSVPs, designed to be opened on phones from a texted link. No guest login or sign-up anywhere. Match this structure exactly: 1. THE FLYER CARD (top of page): - A rounded card (18px corners, soft warm shadow) on a background that fits [THEME / LOOK]. - Header: [EVENT NAME] in spaced capitals with wide letter-spacing, a thin metallic rule under it, then a script headline — a short inviting phrase that fits the event (e.g. "Join us this month for", "You're invited to celebrate", "Save the date for") — then the event's big title line very large in a deep accent serif, with any subtitle in italic serif underneath. - A scene image under the header built around [FEATURE IMAGE], styled to match [THEME / LOOK]. All lettering on the page is real text in web fonts — never bake words into the image; they go soft when people zoom. - A details block under the image: "Hosted by [HOST NAME(S)]", then "[WEEKDAY, DATE] at [TIME]", then [ADDRESS], a ✦ ✦ ✦ divider in the metallic accent, and [INTRO LINE] in warm italics. 2. ACTION BUTTONS under the flyer: - One big pill button in the accent color: "[EMOJI] Tap to RSVP" that scrolls to the RSVP form. - Two smaller pill links beside each other: "📅 Add to Calendar" (a Google Calendar template link pre-filled with the event name, date and time) and "📍 Directions" (a Google Maps link to [ADDRESS] — leave it as a general Maps link if the address is private). 3. A "Good to know" card with my [DETAILS BULLETS]. 4. THE RSVP CARD, headed "RSVP here": - Eyebrow line with [EVENT NAME], the heading "RSVP here", and a sub-line with the date and time. - A form with: "Your name" text field; "Can you make it?" as two big tappable pills — "[EMOJI] Count me in!" (fills with the secondary color when selected) and "Can't make it" (fills soft accent when selected); and "A note for the host (optional)" as a textarea. - A big pill submit button in the accent color: "Send my RSVP ❤️". - Friendly inline error messages if the name or the yes/no choice is missing — and if saving fails, tell the guest to text the host instead. Never fail silently. - After submitting, replace the form with a success state: "You're in, [first name]! [EMOJI]" and "We've got your RSVP — see you [WEEKDAY, DATE] at [TIME]." (or "We'll miss you, [first name] ❤️" for a no), plus an "Update my RSVP" button that brings the form back. 5. A "WHO'S COMING" CARD under the RSVP, visible to everyone on the main page: - Three count boxes across the top: Coming / Can't make it / Responses. - Response cards, newest first: the guest's name in bold, a small tag pill on the right ("Coming" in the secondary tint, "Can't make it" in soft accent), and their note underneath when they wrote one. - A host view at the same link with ?host=1 that adds a "Hide from list" button to each response (two taps to confirm). Hiding removes it from everyone's view. Nothing is ever deleted. DESIGN SYSTEM (derive it from [THEME / LOOK], like this): - Colors: a cream or paper background, paper cards, ONE deep accent (title + main buttons), ONE secondary color (selected states, "Coming" tags), ONE metallic (rules and dividers), a warm ink for text, and hairline borders a shade darker than the background. Worked example — cozy Christmas: cream #faf3e7, paper #fffaf0, red #a52a21, deep red #8c211a, evergreen #2f4a38, gold #b98a2f, ink #3d2c22, line #e6d7bd. - Fonts: a display serif for headings and the title (e.g. Fraunces), a script for the headline phrase (e.g. Great Vibes), a clean caps-friendly sans for the event name and labels (e.g. Jost), and a friendly sans for body text (e.g. Nunito Sans). Swap the script for a different display font if the theme calls for it — keep the four roles. - Page width max 640px, centered, generous padding; rounded corners and soft shadows on every card; a gentle themed particle effect behind everything (falling snow, sparkles, petals — whatever fits [THEME / LOOK]), subtle and non-interactive. Step 2 — Make the RSVPs actually work (this is required, not decoration): - Save every RSVP to Firebase Firestore so the host and all guests share ONE live list. A version that only saves in the visitor's own browser is not acceptable for the real invitation. - One document per guest per event, tagged with an event key for this event, storing: name, attending (yes/no), note, and an updatedAt timestamp. - Remember each guest's document ID in their browser (localStorage) so when they come back they UPDATE their existing RSVP instead of creating a duplicate — prefill their name and note, and show their success state. - Listen for live updates (Firestore onSnapshot) filtered to this event, and re-render the counts and the Who's coming list automatically whenever anyone responds. - Escape guest names and notes when rendering them (never inject raw HTML from a form field). Step 3 — Host it and finish: - Deliver one HTML file (plus the scene image) that I can host free, e.g. on Vercel, at a public link with no sign-in wall for guests. - Set the share-preview (Open Graph) tags: title = [EVENT NAME], description = "[WEEKDAY, DATE] at [TIME]. Tap to RSVP.", image = the flyer/scene image. - Test before you call it done: submit a test RSVP and watch it appear in Who's coming with the counts updated; submit again as the same guest and confirm it updates in place instead of duplicating; check it at phone width. One privacy note: this page is visible to anyone with the link. Only put a home address on it if the host is happy for every guest to have it that way — otherwise use the "Address shared privately" wording and share the address by text.
